# 阶段3B-6.2.3.0 设计：官方指数收益口径核验与基金合同原件获取审计

> **只做官方证据获取、来源核验与覆盖率审计。不接入基准行情，不进入回测。**

**基线 HEAD**：`bc490c339f959b6f5262c90290853612329695e3`

---

## 1. 本阶段要解决的两个证据缺口

| # | 缺口 | 现状（3B-6.2.2.1.1） |
| ---: | --- | --- |
| 1 | 10 个已接入指数 `return_basis` 全为 `unknown` | 0/10 确认，研究基准可用数 0 |
| 2 | 78 只有合同基准文本的基金证据全为 L3 | 0 只取得 L1 合同原件 |

**这两件事都不解决，基准体系无法前进**：没有确认口径就没有合格收益序列；没有 L1 合同就无法把「合同基准」与「研究基准」真正区分开。

---

## 2. 证据等级定义

| 等级 | 定义 | 本阶段允许的用途 |
| --- | --- | --- |
| **L1** | 指数编制机构或官方发布机构原始文件 | 可确认收益口径、可确认合同基准原文 |
| **L2** | 权威正式数据库或官方机构转载 | 仅作交叉验证 |
| **L3** | 第三方聚合资料 | **不得**确认口径、**不得**作为合同证据 |
| **L4** | 无法可靠核验的二手资料或推断 | 仅记录，不得使用 |

## 3. 第一部分设计：10 个指数收益口径核验

### 3.1 官方来源

| 来源 | 用途 | URL 形态 |
| --- | --- | --- |
| 中证指数有限公司官方文档托管 | 编制方案 / 指数单张原件 | `oss-ch.csindex.com.cn/.../zh_CN/<code>_Index_Methodology_cn.pdf` |
| 中证指数官网指数基本信息接口 | 指数全称、发布日、基日、发布机构 | `csindex.com.cn/csindex-home/indexInfo/index-basic-info/<code>` |
| 中证指数官网行情接口 | 实测返回的指数全称与代码 | `csindex.com.cn/csindex-home/perf/index-perf` |

### 3.2 每个指数必须完成的 7 项

| # | 要求 | 实现 |
| ---: | --- | --- |
| 1 | 找到官方编制方案或正式资料 | 真实下载 PDF，非 200/非 PDF 一律记为失败 |
| 2 | 确认正式名称、代码、发布机构 | 官网基本信息接口 + PDF 首页 |
| 3 | 确认官方口径 | **只接受编制方案明文**，见 3.3 |
| 4 | 确认数据库序列对应哪个版本 | 实测 `akshare.stock_zh_index_hist_csindex` 返回的 `指数代码` 与 `指数中文全称` |
| 5 | 核实接口字段是否对应官方口径 | 记录返回列名与样例收盘值；**字段名不含口径信息时不得推断** |
| 6 | 保存原件、URL、披露日期、获取日期、SHA256 | 全部写入 JSON，文件落在 `reports/evidence/phase3B6_2_3_0/` |
| 7 | 无法证明一一对应 → 保持 `unknown` | 见 3.4 的双条件门槛 |

### 3.3 口径判定的严格规则

**只有编制方案明文支持才给结论，其余一律 `unknown`。**

| 判定 | 明文依据 |
| --- | --- |
| 沪深300 = `price` | 编制方案 5.2.1：「凡有样本除息，沪深300指数**不予修正，任其自然回落**」 |
| 沪深300 全收益/净收益为**辅指数** | 编制方案 4.6：「全收益指数、净收益指数是沪深300指数的**辅指数**」 |
| 中证系列规模/主题/行业指数 = `price` | 「四、指数计算」仅用「证券价格×调整股本数」计算调整市值，全文无全收益/红利再投资表述 |
| 上证国债指数 000012 = `full_price` | 官方指数单张把「净价指数」「利息再投资指数」列为**衍生指数**，主序列为全价（含应计利息、不含再投资） |
| 中证红利 = `price` | 股息率加权只改变**加权方式**，不改变「除息自然回落」的价格口径属性 |
| 930930 = `unknown` | 官方单张仅列出「全收益指数 / 净收益指数」衍生代码，**未明文说明主序列口径** |

### 3.4 九维验证状态（3B-6.2.3.0.1 修正）

**原设计的「双条件门槛」把接口代码匹配当成了序列验证，属语义过度表达。**
现拆成九个**独立**状态，逐项判定，不得互相替代：

| # | 状态 | 含义 | 判定依据 |
| ---: | --- | --- | --- |
| 1 | `official_identity_verified` | 官方身份核验 | 代码 + 正式名称 + 发布机构 + 官方文件齐全 |
| 2 | `official_return_basis_verified` | 官方口径核验 | 编制方案**明文**确认口径 |
| 3 | `api_code_identity_verified` | API 代码身份 | 接口返回代码 == 请求代码（**仅身份**） |
| 4 | `api_name_identity_verified` | API 名称身份 | 接口返回全称 == 官方全称（**不能只比代码**） |
| 5 | `database_series_exists` | 库内序列存在 | 只读查 `index_daily` 实际记录 |
| 6 | `database_series_source_traceable` | 数据源可追溯 | source + run_id + row_fingerprint + collected_at |
| 7 | `database_series_numerically_verified` | **数值级官方验证** | 逐日比对中证官网官方收盘值 |
| 8 | `historical_coverage_verified` | 历史连续覆盖 | 交易日历缺失日核验（**本阶段未做**） |
| 9 | `point_in_time_verified` | 时点可用性 | 前视偏差审计（**本阶段未做**） |

**复合结论**（同一指数逐条判断，不得用两个独立计数都 >0 判定）：

```
series_matches_official_basis =
    official_return_basis_verified is True
    AND database_series_numerically_verified is True
```

### 3.4.1 数值级验证的三态

| 情形 | 结果 |
| --- | --- |
| 取得 ≥2 个不同年份官方数值且全部一致 | `True` |
| 取得官方数值但存在不一致 | `False` |
| **取不到官方数值**（限流/无数据） | **`None`（unknown）** |

**「取不到」与「不一致」必须区分**，不得把无证据记为反证据。

### 3.4.2 字段废弃声明

| 旧字段 | 问题 | 处置 |
| --- | --- | --- |
| `series_matched` | 只表示接口代码相等 | → `api_code_identity_verified` |
| `data_series_matches_official` | 被当成数值结论 | **废弃** → `database_series_numerically_verified` |
| `series_matches_official` | 过度表达 | **废弃** → `series_matches_official_basis` |
| `series_probe` | 名称含糊 | → `api_identity` |

### 3.5 000012 的多序列区分（任务特别要求）

实测三个序列是**不同指数**，不能因名称相似认定口径相同：

| 代码 | 官方全称 | 样例收盘（2024-01-02） | 口径 |
| --- | --- | ---: | --- |
| `000012` | 上证国债指数 | 206.07 | 全价（含应计利息） |
| `H00012` | 上证国债指数**(净价)** | 104.65 | 净价（不含应计利息） |
| `N00012` | 上证国债指数**(利息及再投资)** | 145.71 | 含利息再投资 |

**三者点位差近一倍，绝不可互相替代。**

## 4. 第二部分设计：78 只基金 L1 合同原件获取

### 4.1 渠道优先级与实测结果

| 优先级 | 渠道 | 实测结论 |
| ---: | --- | --- |
| 1 | 基金管理人官方网站披露栏目 | **部分可用**：易方达基金官网披露接口可检索并下载合同与招募说明书原件 |
| 2 | 巨潮资讯网（证监会指定信息披露网站） | **仅覆盖场内品种**（LOF / 封闭式 / ETF），场外基金不在收录范围 |
| 3 | 中国证监会资本市场统一信息披露平台 | **只保留最近约 1 个月公告**，无法回溯历年基金合同 |
| 4 | 基金管理人官网其他栏目 | 多数为前端渲染或反爬（阿里云 WAF），本轮未取得 |

### 4.2 每只基金必须记录的字段

`fund_id` / `fund_code` / `fund_name` / 官方文件是否找到 / 文件类型 / 官方来源机构 / 原始 URL / 披露日期 / 文件获取日期 / SHA256 / 是否可正常读取 / 合同基准原文 / 与 L3 是否一致 / 历史版本 / 证据等级 / 未获取原因。

### 4.3 四类文档严格区分

| 类型 | 处理 |
| --- | --- |
| 当前合同原件 | 可作 L1 证据 |
| 历史合同版本 | 单独记录，**不得当作当前版本** |
| 当前招募说明书 | 合同缺失时可作 L2 佐证，**不得冒充合同** |
| 历史招募说明书 | 单独记录，不得回填当前状态 |

**不得用当前版本回填历史合同生效时间。**

### 4.4 合同基准原文提取

只接受**定义式**表述（`业绩比较基准为/：……`），并在句号或正文起始处截断。
「业绩比较基准的紧密跟踪……」这类不含基准定义的句子一律排除。

### 4.5 与 L3 文本的一致性判定

不能只看「包含」——第三方文本可能只是合同基准的一个片段。

| 判定 | 条件 |
| --- | --- |
| 一致 | L3 文本可在合同原文中找到 **且** 权重集合一致 |
| **冲突** | 包含但**权重成分不一致**（典型：L3 漏写成分或写成历史版本） |
| 冲突 | 无法在合同原文中找到 |
