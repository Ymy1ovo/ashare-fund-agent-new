### 1.2 覆盖结论

| 项 | 值 |
| --- | --- |
| 单次长区间请求是否可行 | **否** |
| 按年分段请求是否可行 | 是 |
| 观测到的最早日期 | 2006-03-01 |

| 成功覆盖的年份起点 | [2006, 2010, 2015, 2020, 2025, 2026] |
| **`history_coverage_verified`** | **False** |

> 单次长区间请求失败（返回 0 行），必须按年分段请求；分段可覆盖多个年份，但**不等同于**已验证可稳定取得连续全历史。仍标 history_coverage_verified=false

### 1.3 为什么标 false

| 原因 | 说明 |
| --- | --- |
| 单次 11 年请求返回 0 行 | 接口有隐式区间上限 |
| 2005 整年也返回 0 行 | 最早可用约 2006-03 |
| 按年分段虽可覆盖多年度 | 但**未验证可连续、稳定、无缺地取全历史** |
| 未验证官方公布日历 | 无法判断某日缺数据是「非交易日」还是「真缺」 |

**结论**：可以保留为**候选**数据源，但不能宣称长期历史可用性已验证。

## 4. 期限结构：不能随便挑一个

### 4.1 实测期限利差

| 期限对 | 利差 |
| --- | ---: |
| 10年 - 2年 | **0.3473 个百分点** |
| 30年 - 10年 | 0.4612 个百分点 |

**0.35 个百分点足以让同一只基金的 Sharpe 相差 10%+。**
所以「统一用 10 年期」在本项目里是不允许的。

### 4.2 期限匹配规则（建议，未实施）

| 评估期 | 应使用 | 用错会怎样 |
| --- | --- | --- |
| 近 1 月 | 1 个月期 | 用 10 年会严重高估无风险收益 |
| 近 1 年 | 1 年期国债 / 1Y Shibor | 用 O/N 会低估 |
| 近 3 年 | 3 年期或 1 年期滚动 | 单点忽略利率变化 |
| 成立以来 | 按实际持有期加权 | 单点几乎一定错 |
