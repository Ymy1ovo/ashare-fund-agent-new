## 3. 为什么不能给「买 A 还是 C」的结论

| 原因 | 说明 |
| --- | --- |
| ① 费率来源 | 天天基金第三方数据，**不是支付宝实际费率** |
| ② 历史有效期 | 90 条规则中仅 **11 条**有 `effective_from` |
| ③ 申购费 | 库内只有原费率与平台费率，支付宝优惠未知 |
| ④ 赎回费阶梯 | 部分基金阶梯不连续或有重叠 |
| ⑤ 不得倒推 | 不能用当前费率推历史费率 |
| ⑥ 不得看名字 | A/C 名称本身不说明哪个便宜 |

**另外**：即使成本可算，也只覆盖 3 个有 A/C 双份额的本体，
样本不足以形成一般性结论。

## 4. 持有期成本结构（框架示意）

成本框架按三部分拆分：

| 部分 | 数据来源 | 当前完整度 |
| --- | --- | --- |
| 申购费 | `fund_fee_rules` fee_type=purchase | 阶梯费率有，支付宝优惠未知 |
| 赎回费 | `fund_fee_rules` fee_type=redemption | 阶梯有，但有效期缺失 |
| 销售服务费（年化） | `fund_fee_rules` fee_type=sales_service | 有，A 常为 0，C 通常 0.1%-0.4% |

**总成本 = 申购费 + 赎回费 + 销售服务费 × 持有年数**

三项中任一项 `unknown`，总成本即为 `unknown`，**不当作 0**。
