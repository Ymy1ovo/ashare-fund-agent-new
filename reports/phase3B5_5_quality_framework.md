## 0. 三条铁律

| # | 规则 | 实现方式 |
| ---: | --- | --- |
| 1 | **质量等级只看数据，绝不看收益** | `grade_nav_data()` 的参数只含行数/覆盖/缺口/空值/重复/非正，**不接收任何收益率**；有测试传入正负收益断言等级不变 |
| 2 | **指标级评级独立于基金级** | 13 个指标各自算等级，同一只基金可能「近1年 A、年化 D、Sharpe D」 |
| 3 | **算不出来就标 D / not_available，绝不填数** | 不用 0 冒充无风险利率、不用 0 冒充缺失收益、不把分段回撤包装成全区间回撤 |

## 1. 四级定义

| 级别 | 含义 | 典型触发条件 |
| --- | --- | --- |
| **A** | 数据质量较好，可支持常规描述性研究 | 覆盖 ≥ 3 年、无重复/空值/非正、无超阈值缺口 |
| **B** | 有条件可用，存在明确限制 | 有超阈值缺口，或覆盖 < 3 年 |
| **C** | 证据不足，只能展示有限描述性信息 | 有结构性异常（重复/空值/非正），或覆盖 < 1 年 |
| **D** | 数据不合格，不应生成相关研究结论 | 0 条记录、来源缺失、样本不足 |
| `not_applicable` | 产品类型上不适用 | 货币基金 × 净值型指标 |

**`not_applicable` 不是 D**：货币基金没有净值不是数据差，是产品类型不同。

---

## 2. 基金级评级：只看两个组成

```
overall = worst(序列完整性, 来源可信度)
```

| 组成 | 输入字段 | 不输入 |
| --- | --- | --- |
| 序列完整性 | `rows` / `date_min` / `date_max` / `gap_count_over_threshold` / `null_*` / `duplicate_dates` / `nonpositive_unit_nav` | 任何收益率 |
| 来源可信度 | `source` 字符串 | 任何收益率 |

费率、经理、规模**不参与基金级评级**——它们只影响对应指标，
混进总等级会让「费率缺失」看起来像「净值不可用」。

---

| 代码 | 类型 | 总等级 | 序列 | 来源 | 说明 |

| `001052` | ETF联接基金 | **B** | A（`ok`） | B（`third_party`） | 净值连续性仍为 cannot_verify（无真实公布日历） |
| `001938` | 主动权益基金 | **B** | A（`ok`） | B（`third_party`） | 净值连续性仍为 cannot_verify（无真实公布日历） |
| `000032` | 债券基金 | **B** | A（`ok`） | B（`third_party`） | 净值连续性仍为 cannot_verify（无真实公布日历） |
| `000509` | 货币基金 | **B** | A（`ok`） | B（`third_party`） | 净值连续性仍为 cannot_verify（无真实公布日历） |
| `001548` | ETF联接 A/C 组（A 类） | **B** | A（`ok`） | B（`third_party`） | 净值连续性仍为 cannot_verify（无真实公布日历） |
| `001549` | ETF联接 A/C 组（C 类） | **B** | A（`ok`） | B（`third_party`） | 净值连续性仍为 cannot_verify（无真实公布日历） |

**注意**：全部为 B，原因各不相同——

| 代码 | 为什么是 B |
| --- | --- |
| `050002` | 2003-08-26→2003-09-26 有 31 天缺口 |
| `001052` / `001938` / `000032` / `001548` / `001549` | 序列本身无缺口，但来源是第三方接口（固定 B） |
| `000509` | 同上（货币收益序列无缺口，来源 B） |

> 来源等级固定 B 是设计选择：AKShare 是公开第三方聚合数据，
> 不是基金公司原始披露，也不等于支付宝数据。
> 若要 A，必须有基金公司原始披露或公告级校准数据。

## 4. 三个概念必须分开

| 概念 | 含义 | 本框架怎么体现 |
| --- | --- | --- |
| **基金本身表现差** | 收益低、回撤大 | 只体现在 `7_return_risk` 的数值，**不影响任何等级** |
| **基金数据质量差** | 缺口、空值、来源弱 | 体现在 `4_data_quality_level` |
| **指标计算条件不足** | 缺无风险利率、缺基准、样本不足 | 体现在 `5_indicator_grades` 各指标的 D / not_available |

实测例证：

| 代码 | 近1年收益 | 数据质量等级 |
| --- | --- | --- |
| `050002` | -4.0993% | **B** |
| `001052` | -12.5516% | **B** |
| `001938` | -6.5170% | **B** |
| `000032` | 2.3151% | **B** |
| `000509` | 不适用（货币） | **B** |
| `001548` | -3.3548% | **B** |
| `001549` | -3.3548% | **B** |

收益从 -12.55% 到 +2.32%，覆盖涨跌，但质量等级完全一致——
这就是「收益好坏与数据质量独立」的直接证据。

## 5. 指标级评级：为什么必须分开

`050002` 是最典型的例子：

| 指标 | 等级 | 原因 |
| --- | --- | --- |
| 近1月/3月/6月/1年/3年收益 | **A** | 窗口端点精确命中，窗口内无超阈值缺口 |
| 年化收益 | **D** | 全区间有 31 天缺口，不跨越缺口折算 |
| 日波动率 | **A** | 逐日观测，可算 |
| 年化波动率 | **D** | 年化被缺口阻塞 |
| 最大回撤 | **B** | 分段可观测，可能低估 |
| Sharpe | **D** | 无风险利率不可得 |
| 超额收益 | **D** | 无基准收益序列 |
| 同类比较 | **D** | 同类组仅 1 个本体，样本不足 |
| A/C成本 | `not_applicable` | 单一份额 |

**若只给一个总等级 B**，使用者会以为「B = 整份报告都能看」，
实际上年化、波动率年化、Sharpe、超额收益、同类比较全都不能用。

## 6. 每个指标的输出结构

```json
"ret_12m": {
  "value": -0.040993,
  "status": "ok",
  "quality_level": "A",
  "level_meaning": "数据质量较好，可支持常规描述性研究",
  "evidence": "近1年收益：2025-11-20 → 2026-11-20，3.9812 → 3.818（acc_nav）",
  "limitation": "全区间存在缺口，但本窗口内无超阈值缺口",
  "reason": null
}
```

算不出来时：

```json
"annualized_return": {
  "value": null,
  "status": "insufficient_data",
  "quality_level": "D",
  "evidence": "区间内存在超过阈值的缺口或样本不足",
  "limitation": "不跨越缺口折算年化",
  "reason": "首尾区间内存在 1 处超过 15 天的缺口，不跨越缺口计算年化收益"
}
```

`value` 必须是 `null`，不是 `0`。
