## 1. 512010 剩余 1 股问题的根因

### 1.1 直接原因

`app/backtest/engine.py` 的卖单数量生成使用了 `allow_odd=True`：

```python
quantity = min(round_lot(raw_quantity, rule.lot_size, allow_odd=True), available)
```

`round_lot(..., allow_odd=True)` 等价于 `int(floor(quantity))`，会产生任意整数。

实测链路：

| 步骤 | 数值 |
| --- | --- |
| 512010 持仓 | 130,400 股 |
| 策略按目标权重算出 | 130,399.7 股 |
| `allow_odd=True` 取整 | **130,399** 股 |
| 卖出后剩余 | **1 股** |

### 1.2 为什么会转为负现金

| 步骤 | 数值 |
| --- | --- |
| 剩余 1 股，后续触发卖出 | 1 股 |
| 成交价（含滑点） | 0.3738 元 |
| 成交金额 | 0.3738 元 |
| 最低佣金 | 5.00 元 |
| 佣金 > 成交额 | 是（0.3738 < 5.00） |
| 成交前现金 | 3.99 元 |
| 成交后现金 | 3.99 + 0.3738 − 5.00 = **−1.01 元** |
| 账本检查 | `PortfolioError: 现金为负` |

### 1.3 为什么只影响全池

代表性池的 6 只 ETF 价格区间较宽（0.37 ~ 数元），很少出现「碎股 + 现金接近 0」的组合；
全池 41 只包含大量低价 ETF（512010 约 0.37 元），更容易在碎股卖出时触发。

复现时共发现 **6 笔**非整手卖单，全部来自 `allow_odd=True`：

| 日期 | 卖出数量 | 卖出后剩余 |
| --- | ---: | ---: |
| 2026-08-25 | 130,399 | 1 |
| 2026-10-13 | 73,101 | 1（另有持仓） |
| 2026-10-20 | 175,799 | 1 |
| 2026-10-28 | 1 | 1 → 之后清 |
| 2026-10-29 | 177,599 | 1 |
| 2026-11-03 | 1 | 176,400 |

### 1.4 修复前的账本表现

不是「费用算错」，是「本不该出现的委托数量」。
`portfolio.apply_sell()` 用 `cash += gross - fee` 算术正确，
但结果转负时直接抛异常，中断整个回测。

## 2. 修复采用的交易规则

### 2.1 卖出申报

```python
def sell_quantity(raw_quantity, available, lot_size):
    want = floor(min(raw_quantity, available))
    lots = (want // lot_size) * lot_size
    if lots > 0:
        return lots            # 整手申报
    return min(want, available) # 可卖不足一手 → 整笔清掉零股
```

| 场景 | 规则 |
| --- | --- |
| 可卖 ≥ 一手（100 份） | 按整手向下取整申报 |
| 可卖 < 一手 | 允许一次性全卖（零股处理） |
| 任何情况 | 不超过可卖数量 |

engine 与 broker 两处统一调用，避免下单整手、撮合又变碎股。

### 2.2 卖出净收入不足的防护

```python
if order.side == 'sell':
    net_proceeds = gross - fee
    if net_proceeds < 0 and portfolio.cash + net_proceeds < -1e-6:
        return self._terminate(order, 'sell_proceeds_below_fee', 'rejected')
```

| 情形 | 处理 |
| --- | --- |
| 卖出收入足够 | 正常成交 |
| 收入 < 费用，但现金能补差 | 正常成交 |
| 收入 < 费用，且现金不够 | **拒单**，标记 `sell_proceeds_below_fee`，不制造负现金 |

修复申报数量后该分支在真实数据中不再触发，保留为防御性兜底。

### 2.3 最低佣金模型

`commission = max(成交金额 × 费率, 最低佣金)`，**按每笔实际成交收取一次**。

- 不按股数收取
- 不按日累计
- 同一订单多次撮合，每次成交各收一次（符合「每笔成交」定义）

## 9. 十个问题的明确回答

**1. 512010 剩余 1 股问题的根因是什么？**

卖单申报数量使用了 `round_lot(..., allow_odd=True)`，等价 `floor()` 取任意整数。
持仓 130,400 股、策略算出 130,399.7 股时申报 130,399，卖出后剩 1 股碎股。

**2. 修复采用了什么交易规则？**

卖出按整手申报；只有可卖数量本身不足一手时才允许整笔卖出零股。
engine 与 broker 统一使用 `sell_quantity()`。

**3. 最低佣金是否按正确的委托/成交模型计算？**

是。`max(成交金额 × 费率, 最低佣金)`，按每笔实际成交收取一次，不按股、不按日、不重复。

**4. 全池 sparse_data 是否真正通过？**

**是。** 41 只 ETF、2,004 笔订单、1,235 笔成交、447 个快照，状态 `success`，负现金天数 0。

**5. 是否存在其他 ETF 触发类似问题？**

修复前有 6 笔非整手卖单（全部在 512010）。修复后所有卖单均为整手或「不足一手的整笔清仓」，
全池与代表性池均无碎股产生，负现金天数 0。

**6. 现金账本是否全程非负？**

是。两池所有交易日的 `cash >= -1e-6`，`Portfolio._assert_sane()` 未触发。

**7. 指纹 v3 是否能够检测复权类型变化？**

是。`adjustment_type` 由 `qfq` 改为 `hfq` 时指纹改变，测试 `test_fingerprint_v3_detects_adjustment_type_change` 通过。

**8. MA250 预热是否基于有效价格观测数量？**

是。`valid_prices` 排除 `NaN`、`None`、非正价格；`ok` 判定要求 `valid_prices >= 250`。

**9. 原有 249 项测试是否全部保留并通过？**

是。249 项全部保留，全量 276 项全部通过（新增 27 项）。

**10. 阶段3A.2.1.1 是否正式通过？**

**通过。** 十项验收条件全部满足：
根因已解释、费用模型正确、无绕过账本、全池与代表性池 sparse 均通过、
现金账本非负、指纹 v3 覆盖复权字段、预热按有效价格、原测试全保留、
新增测试全通过、行情未污染、历史记录完整。
