### 1.2 去重规则（本轮核心）

| # | 规则 | 解决的问题 |
| ---: | --- | --- |
| 1 | **同一 `announcement_id` = 同一事件** | 分级 A/B 共用一条公告，不能算两个 |

## 3. 合并事件：0 个，如实报告

### 3.1 尝试过的所有途径

| 途径 | 结果 |
| --- | --- |
| 扫 844 个非存续代码的全部公告标题 | **0 条含「合并」** |
| 扫 16 个代码段（00/01/02/16/21/24/45/48/50/51/52/15/18/56/96/97） | 0 |
| 网络检索「公募基金 合并 并入」 | 只有 REITs 吸收合并、基金公司股权合并，**不是基金合并** |

### 3.2 为什么找不到

中国公募基金的「基金合并」在实践中极少：

1. **法规路径窄**：基金合并需要持有人大会特别决议，流程成本高于直接清盘；
2. **实际操作**：多数基金选择「清盘 + 重新发行」，而不是合并；
3. **公告措辞**：即便有合并，公告也常写成「转型」或「合同终止及财产清算」，
   标题里不出现「合并」二字。

### 3.3 结论

> **不能凑数。合并事件样本 = 0，如实报告。**

这不影响清盘名录的可用性——用户真正关心的是「哪些基金消失了」，
而合并和清盘在「基金本体消失」这一点上效果相同。

但**必须区分**：合并的持有人拿到了承接基金份额，清盘的持有人拿到现金。
对回测而言，前者是「换标的继续持有」，后者是「强制赎回」。
因此 `merge` 与 `liquidation` **不能互相替代**。

### 6.5 当前字段能否无歧义表达区间？

**不能。** 3B-4.0 的 `fund_fee_rules` 只有 `holding_days_min` / `holding_days_max`，
缺三个关键信息：

| 缺失信息 | 为什么重要 |
| --- | --- |
| `min_inclusive` / `max_inclusive` | 「小于365天」与「小于等于365天」在第 365 天费率完全不同 |
| `min_inferred` | 「小于7天」的下界 0 是推断的，不是原文写的 |
| `basis` | 持有期按自然日还是交易日计算 |

**具体反例**：

> `110020` 是「小于等于364天 → 0.50%」，`161725` 是「小于365天 → 0.50%」。
> 两者用 `holding_days_max` 存分别是 364 和 365，**看起来不同但实际等价**。
> 若只看数字会误判为两个不同区间。

### 6.6 最小化字段设计建议（本轮不落地）

| 建议字段 | 类型 | 说明 |
| --- | --- | --- |
| `holding_days_min` | INTEGER | 已有 |
| `holding_days_min_inclusive` | INTEGER 0/1 | **新增** |
| `holding_days_min_inferred` | INTEGER 0/1 | **新增**，标记下界是推断的 |
| `holding_days_max` | INTEGER | 已有，NULL = 无上限 |
| `holding_days_max_inclusive` | INTEGER 0/1 | **新增** |
| `rate_original` | REAL | **新增**（拆分现有 `rate`） |
| `rate_platform` | REAL | **新增** |
| `platform_name` | TEXT | **新增**（eastmoney / alipay / contract） |
| `is_annual` | INTEGER 0/1 | **新增**，区分年化费与一次性费 |

**这套设计的最小性**：只加 6 个字段就能无歧义表达所有已见形态，
不需要引入区间表或 JSON blob。

## 10. 尚未解决的问题

1. 无权威全市场已终止基金全量清单，覆盖率仍不可量化
2. 合并（merge）事件在公告标题里极少显式出现，样本稀薄
3. 承接基金代码公告里基本不写，只能靠名称对回 fund_master
4. 已终止基金的历史费率不可恢复
5. 支付宝可购买状态无公开接口

### 10.1 两条硬限制

**限制 1：合并事件 0 个。**

全市场找不到可验证的「基金合并」案例。这不是检索不够，
是这类业务在中国公募基金里实践极少。

**限制 2：覆盖率仍不可量化。**

43 个清盘本体是「扫描 844 个非存续代码 + 逐只查公告」得到的，
不是从权威全量清单读出来的。真实清盘总数可能更多。

### 10.2 一个仍未修好的小问题

`基金裕泽：终止上市公告` 和 `国泰金象：保本到期转型的第一次提示性公告`
两条的基金名抽取失败（`__no_name__:` 前缀），因为标题只给了简称。

处理方式是**保留为独立本体**（宁可多算不错误合并），
但这意味着这两条的本体键是标题而非基金名。
