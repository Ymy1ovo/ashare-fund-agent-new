## 3. 关键设计决策

### 3.1 为什么用「共同区间」而不是「成立以来」

| 问题 | 说明 |
| --- | --- |
| 成立时间不同 | 2016 年成立的基金比 2009 年成立的少经历一轮牛熊 |
| 直接比成立以来收益 | 等于给老基金额外信息优势 |
| 解决 | 取**交集**，所有参与者都有完整数据的区间 |

### 3.2 为什么年化门槛设为 365 天

不足 1 年的区间年化会放大波动（把 3 个月的涨幅外推成一年），
所以**不足 365 天直接不年化**，返回 `insufficient_data` + 原因。

### 3.3 为什么超额收益恒为 `not_available`

三道闸门**任一**不通过即阻断：

| 闸门 | 当前 |
| --- | --- |
| 指数收益口径 | 10/10 unknown ❌ |
| 复合基准完整性 | 15/15 不可复现 ❌ |
| 基准收益序列 | 库内无此表 ❌ |

所以本阶段**没有任何一只基金**能算超额收益。这不是实现缺陷，
是证据不足的如实反映。

### 3.4 为什么 A/C 成本只给框架不给结论

| 原因 |
| --- |
| 费率来自第三方，不是支付宝实际费率 |
| 90 条规则仅 11 条有 `effective_from` |
| 申购费支付宝优惠未知 |
| 只有 3 个本体有真正的 A/C 双份额 |
