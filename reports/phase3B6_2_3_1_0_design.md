## 3. 九维验证设计

**九维严格独立，不得互相替代。**

| # | 维度 | 判定标准 |
| ---: | --- | --- |
| 1 | `official_identity_verified` | 官方代码 + 中文全称 + 基日 + 发布日齐全，来源为 `csindex.com.cn` |
| 2 | `mapping_to_price_index_verified` | 基日一致 **且** 比值恒 ≥1 **且** 比值随时间上升 |
| 3 | `return_basis_verified` | 官方名称明确含「全收益」或「净收益」 |
| 4 | `history_api_available` | 官方接口返回 **>100 行**完整历史 |
| 5 | `history_coverage_verified` | 相对 A 股日历代理**无缺失交易日** |
| 6 | `data_quality_verified` | 无重复/倒序/非法日期/非数值/NaN/Inf/非正值/空值 |
| 7 | `continuity_verified` | 覆盖通过 **且** 无日历外日期 |
| 8 | `point_in_time_available` | 能证明历史交易日当时已公开 |
| 9 | `formal_series_admitted` | **以上八项全部通过** |

### 3.1 关键设计决策：真实起点识别

官方接口会在**请求起始日**合成一行（3B-6.2.3.0.4 已证实）。
全收益指数的历史回溯起点通常是其**基日**（如 2004-12-31），
首行 `20040101` 与真实起点之间的空档**不是数据缺失**。

因此设计 `_real_history_start()`：

```
若首行与后续行间隔 > 60 天 → 首行为合成/占位行，
真实起点 = 间隔后的第一行
```

**覆盖率核验只从真实起点开始**，避免把「基日前无数据」误判为「缺失 243 个交易日」。

### 3.2 关键设计决策：比值判据

**初版判据「比值恒 ≥1」是错误的**：

- 全收益指数与价格指数**同基点**（1000），基日当天比值必然 **= 1**；
- 实测发现早期（2005-01-04、2006-01-04）比值**恰为 1.0**。

修正为「比值恒 **≥** 1」，并**单独记录比值等于 1 的日期**——
这是「该段未体现分红再投资」的重要事实，必须在报告中披露。

### 3.3 数值关系不得仅凭长期数值高低判定

**不得因为全收益指数长期数值高于价格指数，就直接判定口径正确。**

设计采用三条交叉验证：

| 判据 | 强度 |
| --- | --- |
| 名称含「全收益/净收益」 | 弱（名称相似不足以判定映射） |
| 基日一致 | 中 |
| 比值恒 ≥1 且随时间上升 | 中（符合分红再投资特征，但**不能证明口径**） |

**所有映射结论均标注为「技术判断」，不能替代官方口径文件。**

## 4. 历史时点可用性设计

**当前采集时间和当前下载的数据不能证明历史时点可用。**

| 检查项 | 判定依据 |
| --- | --- |
| 是否有历史快照表 | 查 `sqlite_master` |
| 是否有修订记录 | 查同 `(index_code, trade_date)` 多版本行 |
| 是否能证明当时已公开 | **无证据 → `unknown`** |
| 是否可能事后回溯计算 | **无法排除 → `unknown`** |

**没有历史快照、历史发布时间和修订证据时，必须保持：**

```
historical_point_in_time_availability = unknown
```
