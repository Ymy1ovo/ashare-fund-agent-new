## 2. 第一部分：历史连续性审计设计

### 2.1 日历必须按指数实际市场选择

**不得统一套用一个不适用的交易日历。**

| 指数 | 适用市场 | 日历 | 本阶段是否可用 |
| --- | --- | --- | --- |
| `000300` `000905` `000906` `399997` `H30184` `000942` `000922` | 沪深 A 股 | A 股交易日历 | ✅ 用 `trade_calendar` |
| `000016` | 上海 A 股 | A 股交易日历 | ✅ 用 `trade_calendar` |
| `000012` | 上交所**债券**市场 | 上交所债券交易日历 | ❌ **未独立取得** |
| `930930` | **港股通（香港市场）** | 港股交易日历 | ❌ **未独立取得** |

**关键实测证据**：`930930` 有 **139 条 `valid` 记录不在 A 股交易日历内**（如 `2015-01-01`、`2015-02-18`），证明港股与 A 股交易日不同。**若套用 A 股日历，会把这 139 条真实行情误判为「非交易日错误记录」。**

因此对 `000012` 与 `930930` **不做缺失日核验**，明确标记为「未验证」，而不是用错误日历得出错误结论。

### 2.2 日历证据要求（本阶段的诚实边界）

| 项 | 状态 |
| --- | --- |
| 日历来源 | 本项目 `trade_calendar` 表 |
| 覆盖范围 | 1990-12-19 ~ 2026-12-31，8,797 个交易日 |
| 含周末 | **0 行**（已实测） |
| **是否官方日历** | **❌ 不是**：`trade_calendar` 是 A 股交易日代理，**不是指数编制机构公布的官方发布日历** |
| SHA256 | 见 `coverage_audit.json` 的 `calendar` 段 |

**结论**：即使 8 个 A 股指数「无缺失」，也只能表述为「相对 A 股交易日历无缺失」，**不能表述为「相对官方发布日历无缺失」**。

### 2.3 逐日核验项目

每个指数统计：原始行数、有效行数、suspect 行数、重复日期、日期倒序、非法日期、非正收盘、空值、缺失交易日、非交易日错误记录、最早/最新有效日期、最大连续缺失区间、历史覆盖率。

### 2.4 占位行处理（10 条 `2004-01-01`）

| 要求 | 实现 |
| --- | --- |
| 识别并排除对有效覆盖率的影响 | 计入 `suspect_rows`，不计入 `valid_rows` |
| 不计入有效行情 | ✅ |
| **不删除正式库记录** | ✅ 全程只读 |
| 单独统计 | ✅ `placeholder_rows` 字段 |
| 给出未来清理建议 | 见 recommendation |

## 3. 第二部分：时点可用性审计设计

### 3.1 必须区分的五件事

| # | 概念 | 本阶段结论 |
| ---: | --- | --- |
| 1 | 历史行情**存在** | ✅ 50,603 行 |

| 3 | 历史数据**版本可追溯** | ❌ 每个 (index_code, trade_date) 仅 1 行 |
| 4 | 历史**公开时间可证明** | ❌ 无证据 |
| 5 | 历史**时点可用性可证明** | ❌ 无证据 |

### 3.2 审计项与实测

| # | 检查项 | 结果 |
| ---: | --- | --- |
| 1 | 是否保存历史原始下载文件 | ❌ `reports/evidence/**/raw` 中无 `index_daily` 原始归档 |
| 2 | 是否保存每次采集批次 | ✅ `index_ingest_runs` 10 条 |
| 3 | 是否保存历史数据版本号 | 仅 `index_master.data_version='index-v1'`（当前版本标记，非历史版本链） |
| 4 | 同一日期不同采集时间的多版本 | ❌ **0 行**（实测 `multi_version_rows=0`） |
| 5 | 是否有修订记录 | ❌ 无指数快照表（现有 `*_versions`/`*_snapshots` 表均为基金/ETF 相关） |
| 6 | 能否确认历史数据当时已公开 | ❌ 不能 |
| 7 | 历史行情是否全部集中采集 | ✅ **全部在 `2026-11-23` 一天内采集** |
| 8 | `row_fingerprint` 能证明什么 | **仅当前行内容**，不证明历史版本未被修订 |

### 3.3 关键判定

```
collected_at ≠ 该行情在历史交易日当时已公开
row_fingerprint ≠ 历史版本未被修订
```

**因此：`point_in_time_verified = false`。**

## 4. 第三部分：全收益基准可行性设计

### 4.1 口径分类（严格区分）

| 口径 | 含义 | 适用 |
| --- | --- | --- |
| `price` | 价格指数，除息自然回落 | 股票 |
| `gross_total_return` | 全收益指数，**税前**红利再投资 | 股票 |
| `net_total_return` | 净收益指数，**税后**红利再投资 | 股票 |
| `bond_clean_price` | 债券净价，不含应计利息 | 债券 |
| `bond_full_price` | 债券全价，含应计利息**不含再投资** | 债券 |
| `bond_interest_reinvestment` | 利息及再投资 | 债券 |
| `wealth` | 财富指数，含利息及再投资 | 债券 |

> **债券全价/财富指数与股票全收益指数绝不可混为一谈。**

### 4.2 全收益代码必须来自官方，不得按命名规律猜测

**反例（本轮实测）**：

| 尝试 | 结果 |
| --- | --- |
| `H39997`（按沪深 300 的 `H` + 后 5 位规律猜） | ❌ 不存在 |
| `H20539`（官方实际代码） | ✅ 中证白酒全收益指数 |

**结论**：所有全收益代码必须逐个查官方基本信息接口确认，不能从主代码推导。

### 4.3 三类基准的应用原则

| 类型 | 规则 |
| --- | --- |
| 合同业绩比较基准 | **必须遵循适用时期基金合同**，不得擅自替换成全收益指数 |
| 研究评价基准 | 可考虑全收益指数，但**必须说明与合同基准的差异** |
| 替代基准 | 需显式选择 + 六项说明 |

**不能因为全收益更合理，就直接改写基金合同基准。**
