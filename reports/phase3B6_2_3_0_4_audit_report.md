## 3. 日期语义：四者严格区分

**必须区分四个不同的日期概念，不得混用：**

| 概念 | 含义 | 本阶段结论 |
| --- | --- | --- |
| **官方基日** | 指数官方基本信息中的 `basicDate` | 见下表（2002-12-31 ~ 2014-11-14） |
| **官方发布日期** | 指数正式发布的日期 `publishDate` | 见下表（2003-01-02 ~ 2017-01-16） |
| **API 响应首日** | 本次接口响应的**第一条**日期 | **10/10 均为 `20040101`** |
| **真实最早历史行情日期** | 必须有独立证据确认 | **10/10 均为 `unknown`** |

### 3.2 为什么 API 响应首日不是真实最早历史行情日期

**关键证据**：`API 响应首日` **随请求起始日变化**。

| 请求 | 响应首日 |
| --- | --- |
| `startDate=20040101` | **`20040101`** |
| `startDate=20040102` | **`20040102`**（`20040101` 完全消失） |

**10/10 指数均如此**。一个随请求参数变化而变化的日期，**不可能是指数的真实历史起点**。

### 3.3 重要观察

1. **所有 10 个指数的基日 ≠ 发布日**，两者不可混淆。
2. **API 响应首日一律为 `20040101`** —— 这是「接口把请求起始日当首行」的直接体现，
   与各指数自身基日（2002~2014）无关。
3. `930930` 基日为 `2014-11-14`，但接口从 `20040101` 起请求仍返回该日
   → 进一步证明是合成行而非真实数据。
4. **真实最早历史行情日期：10/10 unknown** —— 未取得可独立证明的官方证据。

### 3.4 措辞边界

- 官方接口原始响应是 **L1 证据**；
- 但「接口为何产生该行」是**根据对照实验得到的技术判断**，
  **不能声称中证官方发布过关于该合成机制的解释或公告**。
