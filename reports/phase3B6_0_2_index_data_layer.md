## 1. 新增表结构（6 张独立表）

| 表 | 用途 | 与基金表关系 |
| --- | --- | --- |
| `index_master` | 指数基础信息 | 无外键关联 |
| `index_ingest_runs` | 采集审计 | 无 |
| `index_daily` | 指数历史行情 | 无 |
| `index_quality_checks` | 质量检查记录 | 无 |
| `benchmark_composite` | 复合基准 | 无 |
| `benchmark_composite_component` | 复合基准成分 | 引用 index_master |

关键设计：

1. `index_daily` 主键 `(index_code, trade_date)`——同指数同日期**物理唯一**；
2. `close` 为 `NOT NULL`——收盘空值无法入库；
3. `row_fingerprint` 记录行内容指纹，识别实际内容变化；
4. `return_basis` 有 CHECK 约束，只能是四种口径之一；
5. `gap_is_real_missing` 恒为 NULL，日历代理无法证明真实缺失；
6. 复合基准成分引用 `index_master`，**不引用任何基金表**。

## 3. 收益口径：全部 unknown

| 口径 | 指数数 | 能否用于总收益比较 |
| --- | ---: | --- |
| `price_return` | 0 | 否 |
| `total_return` | 0 | 是 |
| `net_total_return` | 0 | 是 |
| **`unknown`** | **10** | **否** |

**为什么全是 unknown**：

1. 中证官网 `index-perf` 接口只返回指数**点位**（开高低收），
   不声明该点位序列是否为全收益口径；
2. 沪深300 等指数**同时存在**价格指数（000300）和全收益指数（H00300）等不同版本，
   接口返回的 `000300` 从命名上对应价格指数，但**没有接口字段直接声明**；
3. 按任务书「不得仅凭指数名称或代码推断全收益口径」，
   无字段级证据就不能标 `price_return`，只能 `unknown`。

**后果**：这 10 个指数**只能用于价格走势展示**，
**不能用于正式总收益超额比较**。这是刻意保守，不是遗漏。

## 5. 采集机制

| 项 | 实现 |
| --- | --- |
| 请求方式 | **单次全量请求**（接口实际忽略区间参数，分段只会重复拉全量并触发反爬） |
| 重试 | 最多 6 次，间隔 45 秒（实测 403 反爬约 6 分钟后恢复） |
| 指数间隔 | 6 秒 |
| 失败隔离 | 单指数失败不影响其他（有测试保障） |
| 幂等 | 同内容不写、变了才更新 |
| 事务 | `BEGIN IMMEDIATE` + 显式外键，异常整体回滚 |
| 备份 | 建表前自动备份数据库 |

**重要发现**：中证官网 `index-perf` 接口**忽略 startDate/endDate 参数**，
实测 2004 / 2020 / 全区间三种请求返回完全相同的全量数据。
因此 3B-6.0.1.1 提出的「按年分段」在本接口上无效，改为单次请求 + 重试。
