## 0. 本轮修正的问题

上轮修好了收益口径，但行情可用性判定仍有漏洞：

```sql
SELECT COUNT(*) FROM index_daily WHERE index_code=?   -- 旧写法
```

只数**总行数**，不看 `quality_status`。但 `index_daily` 已有质量状态字段，
且 `effective_date_range()` 明确排除 `suspect` 行。

后果：一个只有 suspect 行（例如全是基线占位值）或只有 1 条有效观测的指数，
会被错误标记为 `data_available=1`。

---

## 1. 有效行情的判定规则（本轮核心）

指数成分必须**同时**满足以下四条，才算 `data_available=1`：

| # | 条件 | 说明 |
| ---: | --- | --- |
| 1 | 指数代码存在 | 未映射 → 不可用 |
| 2 | 收益口径为 `total_return` / `net_total_return` | `unknown` / `price_return` 拒绝 |
| 3 | `index_daily` 中至少 **2 条** `quality_status='valid'` | 一期收益需要两个点 |
| 4 | 这些行的 `close` 为正的有限数 | 空值/0/负数不计 |

### 1.1 明确排除

| 状态 | 是否计入有效观测 | 原因 |
| --- | --- | --- |
| `valid` | ✅ 计入 | 正常行情 |
| `suspect` | ❌ **不计入** | 基线占位行等可疑数据 |
| `rejected` | ❌ **不计入** | 已被拒绝的数据 |

**不得仅用总行数判断数据可用性。**

### 1.2 为什么是 2 条

计算收益序列至少需要两个时间点，才能得到一期收益。
只有 1 条有效观测时，收益序列长度为 0，不构成「可计算收益的历史数据」。

### 1.3 两道防线

| 防线 | 位置 | 作用 |
| --- | --- | --- |
| 第一道 | `index_daily.close NOT NULL` | 空收盘根本进不了表 |
| 第二道 | `count_effective_observations()` | 过滤非 valid、非正值 |

## 2. `evaluate_composite()` 不再信任历史标记

| 项 | 修正前 | 修正后 |
| --- | --- | --- |
| 是否重新读取当前库存 | **否** | **是** |
| 是否重新统计有效行 | **否** | **是** |
| 是否重新读取收益口径 | 是（上轮已加） | 是 |
| 组件 `data_available` 是否刷新 | 否 | **是** |

即使历史组件曾标记可用，只要当前有效行情不足或口径不合格，
整体 `is_reproducible` 一律为 `False`。

这解决了「数据后来被降级/删除，但组件标记没刷新」的陈旧状态问题。

## 7. 3B-6.0.2.3 补充：收盘价「有限正数」校验

原实现用 `c != c or c <= 0` 判断，**只能识别 NaN，漏掉 ±inf**。

修正为：

```python
return math.isfinite(c) and c > 0
```

| 值 | 修复前 | 修复后 |
| --- | --- | --- |
| 有限正数 | ✅ 计入 | ✅ 计入 |
| `+inf` | ❌ **错误计入** | ❌ 不计入 |
| `-inf` | ❌ **错误计入** | ❌ 不计入 |
| `NaN` | 不计入 | 不计入 |
| `0` | 不计入 | 不计入 |
| 负数 | 不计入 | 不计入 |
| `NULL` | 不计入 | 不计入 |

为什么必须用 `math.isfinite`：

- `NaN != NaN` 为真 → `v != v` 能抓到 NaN；
- `inf == inf` 为真 → `v != v` **抓不到 inf**；
- `math.isfinite` 两者都能抓。
