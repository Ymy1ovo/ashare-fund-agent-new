## 0. 核心修正：一个状态拆成五个

### 0.1 修正前（过宽）

| 字段 | 问题 |
| --- | --- |
| `full_history_verified` | **一个 true 掩盖了四种不同事实**：取到了、区间知道、覆盖够、质量好 |

### 0.2 修正后（五态独立判定）

| 状态 | 定义 | 判定依据 |
| --- | --- | --- |
| `history_retrieved` | 接口请求成功且返回非空 | rows > 0 |
| `history_range_verified` | 实际首末日期与行数已核实 | date_min/date_max/rows 齐全 |
| `history_coverage_adequate` | 覆盖率达标 | 真实起点覆盖率 **≥ 95%** |
| `history_quality_adequate` | 质量检查达标 | 重复=0、空值=0、非正=0、**内部缺口 ≤ 20 天** |
| `backtest_usable` | 可回测 | 前四项 + **收益口径已确认** → 本轮恒 false |

### 0.3 ⚠️ 不得自动传递

> **不得因为 `history_retrieved=true` 就自动把后面四项设为 true。**
> 每一项都由独立判据决定，证据附件逐项记录了判定结果与失败原因。

### 0.4 阈值来源声明

- 覆盖率阈值：**95%**（真实起点到最新日期的天数 / 请求区间天数）
- 内部缺口阈值：**20 天**（实测法定长假 11~13 天，20 天可容纳长假并排除真缺失）
- **这是审计口径，不是回测准入门槛**。回测准入门槛需另行立项，本轮不设定。

**不得为了提高可用数量而放宽门槛。**
