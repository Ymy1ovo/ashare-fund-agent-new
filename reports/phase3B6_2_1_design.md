- 基线 HEAD：`13e95a26bfe94f5574febc263304c7fbbc2bc7ab`

## 1. 服务范围

本项目服务对象是**中国公募基金市场**，重点是用户通过**支付宝购买的场外公募基金**。

| 覆盖 | 说明 |
| --- | --- |
| 普通指数基金 | 含增强指数 |
| ETF联接基金 | 场外申购份额 |
| 主动权益基金 | 股票型/混合型非指数 |
| 纯债基金 | 长债/中短债，不含可转债 |
| 混合债券基金 | 含可转债或权益仓位 |
| 货币基金 | 万份收益/七日年化口径 |
| LOF场外份额 | 场外净值，非场内价格 |

**场内 ETF 仅保留历史研究成果，不作为本阶段核心研究对象。**

## 2. 三类基准的严格边界

### 2.1 定义与证据要求

| 概念 | 定义 | 最低证据等级 | 能否升级 |
| --- | --- | --- | --- |
| **`contract`** 合同业绩比较基准 | 来源于基金合同、招募说明书及正式公告的业绩比较基准 | **L1** | **不可升级** |
| **`research`** 研究评价基准 | 为进行基金研究而选择的可比较基准 | **L2** | **不可升级** |
| **`substitute`** 替代基准 | 合同基准不可复现时用于有限研究的替代序列 | **L3** | **不可升级** |

### 2.2 三条硬约束

| # | 约束 |
| ---: | --- |
| — | `contract`：必须保留原始合同文字、证据来源、文件日期与有效期间；不得把第三方平台文本当成官方合同证据；不得用当前合同基准回填历史期间；基准变更必须记录生效日期，历史版本必须保留 |
| — | `research`：可以与合同基准不同，但必须明确选择原因、适用基金类型、选择规则版本，并披露与合同基准的差异；**不得冒充合同业绩比较基准** |
| — | `substitute`：必须明确标记为替代基准；**不得将结果表述为合同基准超额收益**；必须说明替代原因、数据质量与偏差、适用范围与失效条件；**不允许自动升级为正式基准** |

### 2.3 禁止的自动升级

| 从 | 到 | 是否允许 |
| --- | --- | --- |
| platform 文本 | contract | **禁止** |
| research | contract | **禁止** |
| substitute | contract | **禁止** |
| current_weight | historical_weight | **禁止** |

## 3. 七个类别的判定顺序

按 `CATEGORY_PRECEDENCE` 顺序判定，命中即停（避免 ETF联接被误判为普通指数）：

| 序 | 类别 | 判定依据 |
| ---: | --- | --- |
| 1 | `money_market` | `fund_type_l1` 以「货币」开头，或全名含「货币」 |
| 2 | `lof_offexchange` | 基金名称含 `LOF` |
| 3 | `etf_feeder` | 基金名称含「联接」 |
| 4 | `index_plain` | `is_index_fund=1` 或类型/名称含「指数」 |
| 5 | `pure_bond` | 债券型且为纯债/长债（不含可转债、普通债券） |
| 6 | `mixed_bond` | 债券型但含可转债或普通债券 |
| 7 | `active_equity` | 股票型/混合型非指数 |

### 3.1 LOI / ETF联接 是交易形态，不是投资类型

这两个维度**正交**。`classify_fund()` 同时返回：

| 维度 | 取值 |
| --- | --- |
| `required_category` | 七个必需类别之一 |
| `investment_category` | `money_market` / `index_plain` / `active_equity` / `pure_bond` / `mixed_bond` |
| `trading_form` | `etf_feeder` / `lof_offexchange` / `otc_plain` |

**理由**：招商中证白酒(LOF) 的投资类型是指数基金，交易形态是 LOF；
若只保留一个标签，会丢失「它是指数基金」这一关键信息。

## 4. 各类别的基准选择规则

### 4.1 `index_plain` — 普通指数基金

**主基准**：**该基金实际跟踪指数的收益口径**（优先全收益/净收益，非价格）

| 禁止 |
| --- |
| 不得统一映射到沪深300 |
| 不得用价格指数冒充全收益指数 |

**必须声明**：跟踪指数的官方代码；该码对应的收益口径；合同文本是否指明口径

### 4.2 `etf_feeder` — ETF联接基金

**主基准**：**目标指数**的收益口径（与目标 ETF 分开记录）

| 禁止 |
| --- |
| **不得把目标 ETF 的二级市场价格收益当作指数收益** |
| 不得用 ETF 折溢价代替指数表现 |

**必须声明**：目标 ETF 代码；目标指数代码；合同基准写的是 ETF 还是指数

### 4.3 `active_equity` — 主动权益基金

**主基准**：结合投资范围 + 合同基准 + 可比研究指数（如中证800/沪深300）

| 禁止 |
| --- |
| 不得把研究选择的指数说成合同基准 |

**必须声明**：投资范围（A股/港股/行业）；合同基准原文；研究指数的选择理由与规则版本

### 4.4 `pure_bond` — 纯债基金

**主基准**：**与久期匹配的中债/中证债券指数**（区分利率债/信用债/短债/中长期）

| 禁止 |
| --- |
| 不得把净价、全价、财富指数混用 |
| 不得用国债收益率曲线代替债券指数收益率 |

**必须声明**：债券类型（利率债/信用债）；久期区间；指数口径（全价/净价/财富）

### 4.5 `mixed_bond` — 混合债券基金

**主基准**：债券指数 + 权益指数的复合，**必须识别权益仓位与可转债风险**

| 禁止 |
| --- |
| 不得把可转债当纯债 |
| 不得忽略权益仓位对基准的影响 |

**必须声明**：权益仓位上限；是否含可转债；复合权重来源

### 4.6 `money_market` — 货币基金

**主基准**：**万份收益 / 七日年化**独立口径（不与普通净值基金混算）

| 禁止 |
| --- |
| 不得把货币基金当作普通净值基金计算收益率 |
| 不得把 Shibor 直接当作货币基金收益 |

**必须声明**：收益展示口径；是否复权；节假日收益结转规则

### 4.7 `lof_offexchange` — LOF场外份额

**主基准**：**场外份额净值**（与场内交易价格严格分开）

| 禁止 |
| --- |
| **不得因为名称含 LOF 就套用场内价格** |
| 不得用场内折溢价代替场外净值 |

**必须声明**：场外份额代码；场内代码；份额类别（A/C）

## 5. 收益口径：六种绝不可混用

| 口径 | 含义 |
| --- | --- |
| `price` | 价格指数（仅价格变动，不含分红/利息） |
| `total_return` | 全收益指数（价格 + 分红再投资） |
| `net_return` | 净收益指数（扣除税费后的再投资） |
| `full_price` | 全价指数（含应计利息，**不含再投资**） |
| `net_price` | 净价指数（不含应计利息） |
| `wealth` | 财富指数（中债特有，含利息及再投资） |
| `fixed_rate` | 固定年化收益率（合同约定数值，**不是资产权重**） |
| `unknown` | 口径未知 |

**关键不等式**：

| 关系 | 结论 |
| --- | --- |
| 价格指数 vs 全收益指数 | **不等价**，差分红 |
| 全价指数 vs 全收益指数 | **不等价**，全价不含再投资 |
| 净价指数 vs 财富指数 | **不等价**，净价不含应计利息 |
| 固定年化收益率 vs 资产权重 | **不同概念**，不可相加 |
| 活期存款利率 vs 银行间回购利率 | **不同利率** |

## 7. 降级与排除规则

### 7.1 分类置信度

| `classification_source` | 条件 | 置信度 | 可否用于正式统计 |
| --- | --- | --- | --- |
| `primary_field` | `fund_type_l1` 与 `l2` 均非空 | `high` | **可以** |
| `partial_field` | 仅一个非空 | `medium` | 需注明 |
| `name_only_degraded` | 两者均空，仅靠名称 | `low` | **不可以** |

**本轮实测**：主口径 **73** 只 / 部分字段 6 只 / 降级 41 只

### 7.2 基准降级链

```
L1 官方合同文件 + 全部成分可算 + 历史权重可验证
        ↓ 否则
研究评价基准（有可用指数序列）
        ↓ 否则
替代基准（有部分序列，必须标注偏差）
        ↓ 否则
无可用基准（必须输出明确原因）
```

**每一级都必须显式记录 `reasons`，不得静默降级。**

### 7.3 排除规则

| 条件 | 处理 |
| --- | --- |
| 无基准文本 | `parse_status=empty`，不得建立任何基准 |
| 成分权重无法解析 | 不得推断，保留 `weight=None` |
| 所有权重之和 < 100% | 保留 `unexplained_residual`，**不得补成现金** |
| 指数无可用序列 | 列入 `uncomputable_components` |
| 分类字段全空 | 标记 `data_insufficient`，类别不得用于正式口径 |

#### 8.1.1 生命周期互斥分类（3B-6.2.1.1 修正）

数据库中 `lifecycle_status` 实际只有两种取值：

| 原始值 | 数量 | 归类 |
| --- | ---: | --- |
| `unknown` | **79** | **`unknown_status`（状态未知）** |
| `terminated` | **41** | `terminated`（明确终止） |

**没有任何基金被明确标记为存续**（`active`/`existing` 值不存在）。

| 类别 | 数量 | 判定依据 |
| --- | ---: | --- |
| `existing` 明确存续 | **0** | `lifecycle_status ∈ {active, existing}` |
| `terminated` 明确终止 | **41** | `lifecycle_status = terminated` |
| `unknown_status` 状态未知 | **79** | `lifecycle_status = unknown` |
| **合计** | **120** | **守恒校验：True** |

**此前报告把 79 只 `unknown` 当作「存续」，属统计语义错误**——
`unknown` 字面含义就是「状态未知」，不能作为「存续」的证据。
`unknown_status` 的正确算法是**按映射规则直接归类**，不是「terminated 的反集」。
